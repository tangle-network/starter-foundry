## Session Flow Analysis

### FLOW 1: Pursuit ceremony vs. surgical dispatch — both productive, different tools
**Trigger:** plateau-ish signal ("scorecard is lying to us about 3 separate measurements")
**Steps:** `/pursue` spec → 7 coordinated changes → tests → diff audit → Phase 4 evaluation → persist
**Outcome:** architectural gains that wouldn't fit in `/evolve` — staleness gate, inputs manifest, run-weighted metric, test pins, nightly drift workflow
**Followed by:** 3 surgical fixes without ceremony
**Why surgical worked after pursuit:** the measurement integrity layer *enabled* surgical work — after Gen 2 shipped, each failing scenario had a concrete root cause visible in honest data. No generational thesis needed.
**Automation potential:** none — the choice of ceremony vs. surgical is judgment, not mechanism. But the pattern is worth codifying: **pursue when the *measurement* is wrong, surgical when the *measurement identifies a single root cause*.**

### FLOW 2: Audit-rerun orphaning
**Trigger:** kick off long-running `audit-scaffold-quality.mjs` in background
**Steps:** bash run_in_background → process exits with parent shell → output file empty → rerun → fresh process dies too → eventually succeeds on 4th attempt
**Outcome:** lost ~15-20 min of wall time
**Root cause:** `node ... &` inside a Bash tool call with `run_in_background: true` — the `&` backgrounds within the shell, but the shell exits immediately, orphaning the child. The right pattern is `run_in_background: true` WITHOUT `&` — the runtime handles detachment.
**Automation potential:** HIGH — add to `~/.claude/CLAUDE.md` anti-patterns: "never combine `&` with `run_in_background: true`; pick one or the other."

### FLOW 3: Hallucination → operator pushback → cargo-registry recovery
**Trigger:** needed to fix blueprint-sdk Job-trait compile error
**Steps:** (1) proposed `#[blueprint_sdk::debug_job]` hint; (2) operator called it: "no such thing as blueprint_sdk::job, trained on old garbage"; (3) read `~/.cargo/registry/src/index.crates.io-*/blueprint-tangle-extra-0.2.0-alpha.4/` — found real API: `sol!` for SolValue, `.layer(TangleLayer)`, `Caller([u8; 20])` not `Caller(Address)`; (4) fixed, `cargo test --lib` green.
**Outcome:** correct fix, plus a durable data-flywheel lesson
**Why this matters:** fast-moving crates (blueprint-sdk is at 0.2.0-alpha.4, quarterly-ish breaking changes) are exactly where LLM training lag shows up as hallucinated APIs. My own CLAUDE.md has the rule — "WebFetch before third-party API answers" — and I violated it on attempt 1. **Pattern: default to reading the locally-installed source for any non-stdlib API. The crate is cached at `~/.cargo/registry/src/` already; cost is zero.**

### FLOW 4: 80-zero-turn mis-framing
**Trigger:** operator asked "how are you not freaking out" about 80 failures
**Steps:** (1) I had been calling them "failures" in earlier outputs; (2) operator pushed; (3) investigated `sourcePath` → found they were from `gen35-staging-corpus` + `gen36-first-matrix-opencode-glm-51` (BA experimental sweeps); (4) recomputed denominator: they're in the "without-outcome" bucket (253 total → 173 withOutcome), already excluded from `buildout_pass_rate`; (5) corrected framing: "not our bug, not our regression"
**Outcome:** correct mental model; operator validated ("these are from the BA not from here ya?")
**Why I got it wrong initially:** surface inspection of `perScenario` showed scenarios with `pass: 0/N, meanTurns: 0` — looks like failures. Didn't reconcile against the summary `totalFailing: 26` which already excluded them. **Pattern: when a number feels alarming, reconcile against every summary it could be miscounting.**

### FLOW 5: Derivation bug as force multiplier for honesty
**Trigger:** Gen 2 audit-script fix for split-framework layer-id derivation
**Observation:** Pre-Gen-2 audit reported 0.851 pass rate. Post-Gen-2 it reported **0.809** — WORSE. Then Gen 3's tailwind-compat fix jumped it to **0.9787**.
**Why it got temporarily worse:** the derivation bug was masking 10 layer failures as "unknown layer" errors, which somehow counted as pass in the old code path (or never reached the smoke-compose phase). Fixing the derivation bug *exposed* those 10 + 16 pre-existing tailwind-incompat failures that the old bug was also hiding.
**Lesson:** honest measurement makes things look *worse* before they get better. If I'd only looked at the aggregate number, Gen 2 would have read as a regression. It was actually the thing that made Gen 3's 16-failure single-fix possible. **Pattern: when a fix decreases an aggregate, investigate whether it's because the fix exposed previously-hidden signal. A 0.851 → 0.809 drop that unblocks 16 concrete fixes is net positive; a 0.851 → 0.809 drop from real regression is net negative. Same number, opposite verdicts.**
