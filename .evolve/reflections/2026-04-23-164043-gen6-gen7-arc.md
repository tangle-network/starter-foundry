## Product Signals

1. **"Evolve plateau might be dataset plateau, not metric plateau."** This is a commercial insight for the eval-platform space. Most eval tools assume the dataset is correct; Variant A's finding shows the dataset itself can be the ceiling. A tool that continuously audits trace completeness (null-field detection, orphan-correlation-id detection, etc.) would save teams from chasing phantom metrics.

2. **"Multi-pursue's comparative advantage is DIAGNOSTIC yield, not just metric yield."** Running A + B in parallel yielded the metric winner AND a previously-unknown upstream bug. Sequential evaluation of variants under time pressure would have merged B and shipped — leaving A's diagnostic on the floor. Implication: parallelism-for-diagnostics is a distinct product from parallelism-for-speed.

3. **"Judge rubric is a prompt, and prompts need AxGEPA-style optimization."** The R3→R4 single-sentence fix that flipped 3 drafts is exactly the kind of improvement AxGEPA could automate given a training corpus. The 5 (prompt, outcome, revert-reason) triples from this arc are now that corpus. Who would pay: teams building LLM-judge pipelines (most AI eval products today ship hand-tuned rubrics that silently Goodhart).

## Durable patterns (saved to memory/)

1. **Parallel worktrees surface diagnostics that sequential evolve misses.** Multi-pursue protocol's worktree isolation is load-bearing, not cosmetic. Applies whenever N variants target the same file.
2. **Partner metadata > prompt text when prompt text is unreliable.** Routing-signal population density beats resolution. Applies to any router/dispatcher design.
3. **Judge rubric calibration can be THE blocker.** A single-sentence signature change can flip verdicts across the entire corpus. Check the judge before optimizing the generator.
4. **"Shipped but unwired" is a common bug class.** Gen N flips a default on; Gen N+1 discovers callers never opted in. Audit defaults during Phase 1.5 of every round.
5. **Revert-aware scorecard semantics require timestamp-awareness.** Naive "subtract all reverted ids" blocks legitimate re-promotes. Match `promote-reverted` events against `promoted` events by id AND timestamp — only subtract promotes that happened AT OR BEFORE the revert ts.
