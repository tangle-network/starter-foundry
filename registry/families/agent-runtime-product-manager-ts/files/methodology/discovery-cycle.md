# Discovery Cycle

## Overview
A structured process to reduce risk before building by testing assumptions with real users.

## Phases

### 1. Frame
- What is the decision we need to make?
- What is the riskiest assumption?
- What would we do differently if we knew the answer?

### 2. Design
- What method will we use? (interview, survey, prototype test, A/B test, data analysis)
- Who will we talk to? (target customer segment, sample size)
- What questions will we ask? (open-ended, avoid leading)

### 3. Execute
- Conduct the research. Record observations, not interpretations.
- Capture verbatim quotes, behaviors, and emotional reactions.

### 4. Analyze
- What patterns emerged?
- What did we learn about the assumption?
- What new questions arose?

### 5. Decide
- Based on the evidence, do we proceed, pivot, or kill?
- What is the next riskiest assumption to test?

## Output
A discovery brief with:
- Decision made
- Evidence summary
- Next steps

## Usage
Run the cycle iteratively. Each cycle should take no more than 2 weeks. Start with the riskiest assumption.
